# Current State Audit

## Summary

This is not a production-ready product; it is a partially wired LMS with real auth, admin CRUD, progress records, quizzes/tests, and certificate generation paths, but the core paid enrollment and assessment-integrity requirements from `PRODUCT.md` are not met. The canonical product requires `login -> dashboard -> lesson -> quiz -> 80% gate -> chapter test -> unlock -> certificate` (`PRODUCT.md:38`, `PRODUCT.md:44`), while the code adds a final exam gate and issues certificates only after passing that final exam (`Back-End/src/controllers/courseController.ts:1469`, `Back-End/src/controllers/courseController.ts:1511`). Payment is required by the product (`PRODUCT.md:107`, `PRODUCT.md:115`) but there is no payment backend and the frontend routes unpaid users to a missing `/purchase` page (`Front-End/src/pages/CourseDetail.tsx:104`, `Front-End/src/App.tsx:1`). The server has useful authorization primitives, but strict progression is inconsistently enforced because lesson content and lesson quizzes can be fetched by ID without applying the access controller (`Back-End/src/controllers/courseController.ts:153`, `Back-End/src/controllers/courseController.ts:207`). Existing tests do not pass: backend Jest failed 2/11 suites, and frontend Vitest failed 7/32 test files with 51 failing tests and 1 unhandled test error in this audit run.

## Stack & Architecture

- Backend: Node/TypeScript Express app with scripts for dev/build/start/test in `Back-End/package.json:6`; Express is declared in `Back-End/package.json:24`, Mongo/Mongoose in `Back-End/package.json:28`, TypeScript in `Back-End/package.json:52`, and `ts-node-dev` in `Back-End/package.json:51`.
- Frontend: Vite + React + TypeScript app with scripts in `Front-End/package.json:6`; Vite is used for dev/build (`Front-End/package.json:7`, `Front-End/package.json:53`), React is declared in `Front-End/package.json:28`, and TypeScript in `Front-End/package.json:52`.
- App split: backend source is under `Back-End/src` and frontend source under `Front-End/src`; there is no top-level monorepo package/workspace file in the repo file list, so dependency management is split between `Back-End/package.json` and `Front-End/package.json`.
- Data lives in MongoDB through Mongoose models: users (`Back-End/src/models/User.ts:31`), courses (`Back-End/src/models/Course.ts:19`), chapters (`Back-End/src/models/Chapter.ts:20`), lessons (`Back-End/src/models/Lesson.ts:20`), questions (`Back-End/src/models/Question.ts:15`), progress (`Back-End/src/models/UserProgress.ts:40`), test sessions (`Back-End/src/models/TestSession.ts:21`), certificates (`Back-End/src/models/Certificate.ts:18`), and settings (`Back-End/src/models/Settings.ts:34`).
- Backend boot requires `FRONTEND_URL` and `MONGODB_URI` and throws if missing (`Back-End/src/server.ts:21`, `Back-End/src/server.ts:61`); it connects to Mongo and listens directly from `server.ts` (`Back-End/src/server.ts:66`).
- Deployment story is local/manual only in docs: README gives local `.env` and `npm run dev` instructions (`README.md:48`, `README.md:76`); no CI/deployment config appeared in the repo scan.
- Dependency freshness: `npm outdated --json` on 2026-08-10 reported backend runtime packages behind latest including `mongoose`, `nodemailer`, `openai`, and frontend packages behind latest including `vite`, `react-router-dom`, `axios`, `react`, `tailwindcss`, and `typescript`; package manifests are cited above.

## What Actually Works (verified, end to end)

- No complete browser-to-backend product journey was verified end to end in this audit. The test suites fail, and no live Mongo/HTTP/browser run of the full login-to-certificate journey was completed.
- Fragment-level code paths exist and are covered by some passing tests: backend auth tests passed in the `npm.cmd test -- --runInBand` run, and frontend component/page tests had 713 passing tests in the `npx.cmd vitest run --reporter=dot --silent` run.
- Server-side role enforcement exists for protected APIs: course routes mount `authMiddleware` and `requireStudent` before protected student routes (`Back-End/src/routes/courseRoutes.ts:24`, `Back-End/src/routes/courseRoutes.ts:25`), and admin routes mount `authMiddleware` plus `requireAdmin` (`Back-End/src/routes/adminRoutes.ts:31`, `Back-End/src/routes/adminRoutes.ts:32`).
- JWT invalidation exists: `authMiddleware` re-reads user role/tokenVersion from Mongo on every request (`Back-End/src/middleware/authMiddleware.ts:33`, `Back-End/src/middleware/authMiddleware.ts:42`), and role changes go through `user.save()` after setting `user.role` (`Back-End/src/controllers/adminController.ts:1111`).

## What Partially Works (and exactly where it stops)

- Auth partially works: register/login/verify/reset routes exist (`Back-End/src/routes/authRoutes.ts:19`, `Back-End/src/routes/authRoutes.ts:20`, `Back-End/src/routes/authRoutes.ts:21`, `Back-End/src/routes/authRoutes.ts:23`), and frontend auth stores the JWT in localStorage (`Front-End/src/context/AuthContext.tsx:25`, `Front-End/src/context/AuthContext.tsx:51`). It stops short of paid enrollment because newly registered users remain role `User` by default (`Back-End/src/models/User.ts:48`) and no payment flow upgrades them.
- Dashboard partially works: frontend fetches detailed progress (`Front-End/src/pages/Dashboard.tsx:25`) and backend computes `nextAction` from progress (`Back-End/src/controllers/courseController.ts:535`, `Back-End/src/controllers/courseController.ts:635`). It stops at advisory/navigation gating; direct content endpoints do not reuse that gate.
- Lessons partially work: `getLesson` returns published lesson content (`Back-End/src/controllers/courseController.ts:153`, `Back-End/src/controllers/courseController.ts:186`), and `LessonView` renders it (`Front-End/src/pages/LessonView.tsx:162`). It stops because `LessonView` fetches the lesson before the separate access check (`Front-End/src/pages/LessonView.tsx:30`, `Front-End/src/pages/LessonView.tsx:44`), and backend `getLesson` itself does not enforce progression.
- Lesson quizzes partially work: quiz questions are fetched without correct answers (`Back-End/src/controllers/courseController.ts:207`), submissions are scored server-side (`Back-End/src/controllers/courseController.ts:291`, `Back-End/src/controllers/courseController.ts:301`), and passing updates progress (`Back-End/src/controllers/courseController.ts:344`, `Back-End/src/controllers/courseController.ts:360`). It stops because failed quiz attempts are not recorded and quiz access is not server-gated against previous lessons.
- Chapter tests partially work: starting a chapter test checks all lessons in that chapter for regular users (`Back-End/src/controllers/courseController.ts:780`, `Back-End/src/controllers/courseController.ts:784`), creates a session (`Back-End/src/controllers/courseController.ts:838`), and submission records an attempt (`Back-End/src/controllers/courseController.ts:1045`). It stops because timing is not per product spec and expiry is not explicitly checked at submit time.
- Certificates partially work: passing the final exam sets completion/certificate flags (`Back-End/src/controllers/courseController.ts:1469`, `Back-End/src/controllers/courseController.ts:1472`) and creates two certificate records (`Back-End/src/controllers/courseController.ts:1511`, `Back-End/src/controllers/courseController.ts:1526`). It stops because `PRODUCT.md` specifies a certificate after all chapters are done, not after an added final exam (`PRODUCT.md:44`), and the code issues an extra HIPAA certificate not described as v1 scope.

## What Is Missing (required by PRODUCT.md, absent in code)

- Payment integration is absent. Product requires course one-time payment and launch payment support (`PRODUCT.md:107`, `PRODUCT.md:115`); code search found no Stripe/payment/checkout/subscription backend routes or dependencies, and unpaid-user CTAs navigate to missing `/purchase` (`Front-End/src/pages/Landing.tsx:118`, `Front-End/src/pages/CourseDetail.tsx:104`).
- Server-authoritative 30-second timing is absent. Product requires 30 seconds per question globally and server-side timing (`PRODUCT.md:61`, `PRODUCT.md:65`); backend chapter tests return `timePerQuestion: 60` and 40-minute expiry (`Back-End/src/controllers/courseController.ts:845`, `Back-End/src/controllers/courseController.ts:857`), and final exam returns `timePerQuestion: 60` with 100-minute expiry (`Back-End/src/controllers/courseController.ts:1284`, `Back-End/src/controllers/courseController.ts:1296`).
- Focus-loss logging/flagging is absent. Product says focus loss is logged and flagged, never instant fail (`PRODUCT.md:69`); frontend chapter/final exams abandon immediately on `visibilitychange` (`Front-End/src/pages/ChapterTestView.tsx:106`, `Front-End/src/pages/FinalExamView.tsx:130`), and no model field exists for focus events in `TestSession` (`Back-End/src/models/TestSession.ts:21`).
- Reconnect grace window is absent. Product requires a brief reconnect grace (`PRODUCT.md:65`); `TestSession` stores `startedAt`, `expiresAt`, and booleans only (`Back-End/src/models/TestSession.ts:45`, `Back-End/src/models/TestSession.ts:49`, `Back-End/src/models/TestSession.ts:53`).
- Complete course material is not present in the repo. Lesson content is a Mongo field (`Back-End/src/models/Lesson.ts:20`, `Back-End/src/models/Lesson.ts:39`) and admin-created HTML (`Back-End/src/controllers/adminController.ts:463`), but there are no seed/content files in the scanned repository.
- Post-course subscription services are absent from backend models/routes. Product defines Tier 1/Tier 2 subscription services (`PRODUCT.md:90`), but no subscription/payment/service models or routes were found in `Back-End/src`.

## Security Findings (severity-ranked)

- Critical: local backend `.env` contains live-looking secrets for Cloudinary, Google OAuth, JWT/session, Mailtrap, MongoDB, and OpenAI (`Back-End/.env:2`, `Back-End/.env:8`, `Back-End/.env:9`, `Back-End/.env:14`, `Back-End/.env:15`). `Back-End/.env` is gitignored (`Back-End/.gitignore:3`) and was not tracked by `git ls-files`, but the secrets are present on disk in this workspace.
- High: strict course-content authorization is not enforced at the content endpoint. `getLesson` returns `lesson.content` by ID (`Back-End/src/controllers/courseController.ts:153`, `Back-End/src/controllers/courseController.ts:186`), while access gating is a separate endpoint (`Back-End/src/routes/accessRoutes.ts:8`); `LessonView` fetches content before running `checkLessonAccess` (`Front-End/src/pages/LessonView.tsx:30`, `Front-End/src/pages/LessonView.tsx:44`).
- High: assessment timing is not authoritative as specified. Submit handlers reject submitted/abandoned/inactive sessions (`Back-End/src/controllers/courseController.ts:985`, `Back-End/src/controllers/courseController.ts:990`, `Back-End/src/controllers/courseController.ts:995`, `Back-End/src/controllers/courseController.ts:1388`, `Back-End/src/controllers/courseController.ts:1393`, `Back-End/src/controllers/courseController.ts:1398`) but do not compare `expiresAt` to current server time in the submit path.
- High: payment authorization is nonexistent. `requireStudent` treats role as subscription proof (`Back-End/src/middleware/roleMiddleware.ts:19`, `Back-End/src/middleware/roleMiddleware.ts:34`), and admins can set that role manually (`Back-End/src/controllers/adminController.ts:1094`, `Back-End/src/controllers/adminController.ts:1111`), but there is no payment-provider verification.
- Medium: JWT is stored in localStorage (`Front-End/src/context/AuthContext.tsx:25`, `Front-End/src/context/AuthContext.tsx:51`), increasing exposure if any XSS exists.
- Medium: lesson HTML is rendered with `dangerouslySetInnerHTML` (`Front-End/src/pages/LessonView.tsx:162`). If malicious HTML enters lesson content through admin CRUD (`Back-End/src/controllers/adminController.ts:463`), the frontend renders it directly.
- Medium: certificates persist student email and identity data (`Back-End/src/models/Certificate.ts:7`, `Back-End/src/controllers/courseController.ts:1515`) and public verification returns certificate holder name/course metadata when certificate number and verification code match (`Back-End/src/controllers/courseController.ts:1711`, `Back-End/src/controllers/courseController.ts:1720`).
- Low: `Front-End/.env` is tracked and present in history (`Front-End/.env:1`, `Front-End/.env:3`, `Front-End/.env:4`). It contains public `VITE_*` values, not server secrets, but it hard-codes environment-specific IDs/URLs in Git.

## Risks

- Certificate credibility risk: the product thesis depends on assessment integrity (`PRODUCT.md:56`), but the code does not implement the specified 30-second server-authoritative timer or focus-loss flagging (`Back-End/src/controllers/courseController.ts:857`, `Front-End/src/pages/ChapterTestView.tsx:106`).
- Revenue/access risk: there is no payment integration, and the purchase path is missing (`Front-End/src/pages/CourseDetail.tsx:104`, `Front-End/src/App.tsx:35`).
- Data exposure risk: locked lesson content can be fetched before access denial in the UI (`Front-End/src/pages/LessonView.tsx:30`, `Front-End/src/pages/LessonView.tsx:44`).
- Operational risk: both test suites currently fail, so regressions can merge unnoticed unless checked manually.
- Compliance/privacy risk: student identity and certificate data are persisted (`Back-End/src/models/Certificate.ts:7`, `Back-End/src/models/Certificate.ts:18`) without visible retention, deletion, audit, or payment-data policy code.
- Delivery risk: the app depends on external MongoDB, Cloudinary, OpenAI, Google OAuth, and email configuration (`README.md:44`, `README.md:58`), but deployment and environment management are not defined beyond local setup.
